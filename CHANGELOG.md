# Изменения

## 2.5.0
**Безопасность**
- Новые ключи выводятся через **scrypt** (128 МиБ памяти на попытку): перебор на видеокартах
  дорожает в сотни раз по сравнению с PBKDF2. Слабые фразы (короче 10 символов, «123456789»,
  «qwertyuiop», повторы) для новых ключей не принимаются. Ключи PBKDF2 (2.4) и старого формата
  работают как раньше; кнопка со щитом создаёт из того же слова ключ scrypt.
- Пароль на программу — тоже через scrypt со случайной солью; старые хранилища переводятся
  автоматически при первом вводе пароля. После неверного пароля пауза растёт (до 30 с).
- Исправлено: «Сменить ключ файла» не проверял, что файл действительно зашифрован текущим ключом,
  и мог безвозвратно испортить файл с другим ключом. Теперь у каждого файла берётся его ключ,
  а перешифровка без проверки невозможна.
- Исправлено: проверка ключа для `.vids` принимала чужой ключ в 1 случае из 256 (сигнатура
  MPEG-TS из одного байта); у картинок — в 1 из 65 536. Сигнатуры проверяются строже.
- Исправлено: «Объединить» склеивал файлы с разными ключами и повреждённые (длина не кратна 16),
  после чего «съезжали» все следующие кадры. Теперь файлы перешифровываются к одному ключу,
  повреждённые не склеиваются.
- Исправлено: «удалить оригиналы» перемещал незашифрованные оригиналы в корзину, где они так и
  лежали открытыми. Теперь оригинал удаляется безвозвратно и только после проверки, что
  зашифрованная копия расшифровывается в точности в него.
- Исправлено: повреждённый `keystore.json` при следующем сохранении затирался пустым
  хранилищем (ключи терялись). Теперь он откладывается в `keystore.json.broken-…`.
- Исправлено: видеоплеер продолжал расшифровывать видео прежним ключом после смены активного.

**Новое**
- **Все ключи сразу**: файлы открываются любым ключом из списка — нужный подбирается
  автоматически. Активный ключ — только для новых файлов.
- **Помнить пароль** 5 минут … сутки (в памяти сеанса, `$XDG_RUNTIME_DIR`), «Заблокировать
  сейчас» — Ctrl+L, `jpgs lock`.
- **Видео и картинки в одном архиве** (архив v2: индекс дописывается в конец файла, данные не
  перезаписываются; старые `.jpgs` без видео и заметок остаются в прежнем формате).
  Перетаскивание видео в открытый архив, «В один архив…» при шифровании, «Объединить файлы в
  один архив…», `jpgs pack`.
- **Заметки** к картинкам и видео (N): хранятся в файле зашифрованными, показываются поверх,
  отмечаются ✎ на миниатюре; `jpgs note`.
- **Сжатие и конвертация через FFmpeg** без расшифровки на диск: формат, качество, разрешение,
  кадры в секунду, звук, обрезка; для картинок — JPEG/PNG/WebP, качество, размер.
- Исправлено: правый клик по ленте миниатюр открывал системное меню окна (лента лежала в
  области перетаскивания окна). Теперь правый клик по миниатюре открывает меню JPGS для этой
  записи.
- Окно ключей: отпечаток и вывод ключа считаются в фоне — окно больше не подвисает на каждой букве.
- Открытие обычной картинки через «Открыть» предлагает её зашифровать, а не показывает ошибку.
- Настройки пишутся атомарно (сбой посреди записи не портит `settings.json`).
- Исправлено: `jpgs encrypt -o ПАПКА` падал, если папки ещё нет; ошибка с одним файлом
  больше не обрывает обработку остальных.
- `install.sh` спрашивает, из какой версии ключ, — ключ уже зашифрованных файлов добавляется
  в нужном формате (`set-key --legacy` / `--pbkdf2`), а не как новый.
- **Лента миниатюр: файлы ↔ кадры.** Слева в ленте два переключателя: «файлы папки» (как раньше)
  и «кадры текущего файла» — все изображения внутри открытого `.jpgs` с номерами, клик открывает
  нужный кадр. При переходе в другой файл лента показывает уже его кадры. Shift+T переключает
  режим, выбор запоминается. Лента теперь видна и когда в папке один файл, но в нём много кадров.
- **Анимированные GIF сохраняют анимацию.** Раньше GIF при шифровании превращался в JPEG — оставался
  только первый кадр. Теперь анимированный GIF шифруется в `.vids` байт в байт, играет в плеере
  по кругу (независимо от «Повторять видео») и расшифровывается обратно в `.gif`. Статичный GIF,
  как и прежде, становится кадром `.jpgs`.
- В архив `.jpgs` анимированный GIF добавляется как видео-запись (анимация сохраняется).
- `.webm` по-прежнему поддерживается как видео; `jpgs encryptor` теперь распознаёт видео и GIF
  той же функцией, что и окно программы.

## 2.4.1
- Ключевое слово больше не хранится в `keystore.json`: в записи остаются только готовые байты
  ключа (`material`). Существующие файлы чистятся автоматически при первой загрузке — ключ
  продолжает работать, слово из файла исчезает.
- Это не защищает файлы само по себе: `material` и есть ключ, и кто прочитал хранилище — тот
  открывает всё. Смысл в другом: слово люди переиспользуют как пароль в других местах, и ему
  незачем лежать на диске открытым. От чтения хранилища защищает только пароль на программу.
- Для ключей старого формата слово при необходимости восстанавливается из самих байтов (там оно
  и было ключом) — этого хватает для усиления ключа и для совместимости со старыми версиями.
  У усиленных ключей слово не восстанавливается: помните его сами.

## 2.4.0
- **Ключ усиливается.** Раньше введённое слово становилось ключом AES напрямую (байты строки,
  добитые нулями) — короткое слово подбиралось словарём почти мгновенно. Теперь слово проходит
  через PBKDF2-HMAC-SHA256 (300 000 итераций) и даёт полноценные 256 бит; одна попытка перебора
  дорожает примерно в 300 000 раз. Для пользователя ничего не меняется: вводится то же слово.
- Соль намеренно фиксированная, а не случайная: то же слово на другом компьютере даёт тот же
  ключ, поэтому файлы открываются и без переноса `keystore.json` (а его потеря при известном
  слове не означает потерю файлов).
- **Старые файлы продолжают открываться.** Ключ из прежних версий переносится в хранилище как
  «старый формат» и работает как раньше. Такой ключ можно усилить кнопкой со щитом в *Ключи
  шифрования…* (или `jpgs keys upgrade <id>`): создаётся второй ключ из того же слова, после чего
  файлы переводятся на него — «Сменить ключ у всех файлов папки…» либо
  `jpgs keys upgrade <id> --rekey ФАЙЛЫ --activate`.
- Ключ старого формата можно добавить вручную (галочка «Ключ из прежних версий JPGS» в диалоге
  добавления, `--legacy` в CLI) — чтобы открыть файлы, зашифрованные прежней версией на другой
  машине.
- Новая переменная окружения `JPGS_WORD` — слово нового формата; `JPGS_KEY` по-прежнему означает
  ключ старого формата, поведение скриптов не меняется.

## 2.3.0
- Несколько ключей в одном хранилище (`~/.config/jpgs/keystore.json`): добавление, удаление,
  переименование, выбор активного — в окне *Меню → Ключи шифрования…* и командой `jpgs keys`.
- Необязательный пароль на программу: если задан, список ключей хранится зашифрованным
  (PBKDF2-HMAC-SHA256 + AES-256-CBC + HMAC), сам пароль на диск не пишется. При запуске
  программа спрашивает пароль. Старый открытый файл `key` при установке пароля удаляется.
- Смена ключа у файлов без расшифровки на диск: «Сменить ключ файла…» в контекстном меню и
  «Сменить ключ у всех файлов папки…» в меню; в CLI — `jpgs keys rekey ФАЙЛЫ --to <id>`.
- Кадр в архиве теперь можно переместить на конкретный номер (диалог с вводом номера),
  а не только сдвигать влево/вправо.
- Лента миниатюр прокручивается колесом мыши.
- Исправлено сохранение кадра видео в PNG: кадр декодируется через PyAV (надёжно при
  аппаратном декодировании), а не через screenshot mpv.
- Совместимость: старый одиночный ключ из `~/.config/jpgs/key` автоматически переносится
  в хранилище; без пароля активный ключ дублируется обратно в этот файл для старых версий.

## 2.2.0
- Встроенный ключ шифрования удалён: ключ задаётся при установке (`install.sh`), командой
  `jpgs set-key` или в окне программы при первом запуске. Хранится в `~/.config/jpgs/key` (права 600).
- Перетаскивание изображений/`.jpgs` в окно с открытым `.jpgs` дописывает кадры в этот файл
  (без создания копий).
- Контекстное меню (правый клик) для изображения, архива и видео: сдвиг/удаление/вынос кадра,
  разделение архива, скорость видео, сохранение кадра, переименование, «Показать в папке», свойства.
