# JPGS — зашифрованная галерея изображений и видео для Linux

**Просмотрщик личных фото и видео, которые хранятся на диске в зашифрованном виде (AES-256).**
Файлы расшифровываются только в памяти: на диск ничего не пишется, в историю системы ничего не попадает.
GTK 4 + libadwaita, нативно под Wayland, видео через libmpv / FFmpeg.

## Возможности

**Изображения (`.jpgs`)**
- Листание кнопками ← → (в заголовке и по краям), кликом у края, стрелками; лента миниатюр внизу
  переключается между файлами папки и кадрами внутри открытого файла (Shift+T).
- Масштаб колёсиком к курсору, щипком, клавишами; двойной клик — вписать ↔ увеличить; до 2000%.
- Масштаб и сдвиг считает видеокарта. Кадр декодируется под размер экрана, полное разрешение
  подгружается только при увеличении, соседние кадры — заранее. Листание мгновенное, памяти мало.
- Поворот, учёт EXIF-ориентации, полный экран, слайд-шоу.

**Файл `.jpgs` — это архив кадров.** В одном файле может лежать много изображений:
- перетащите картинку или другой `.jpgs` в окно — кадры **допишутся в открытый файл**, без копий
  и без пересборки;
- правый клик → переместить кадр на нужный номер, удалить, вынести в отдельный файл, разделить
  архив на файлы.

**Архив с видео и заметками.** В один `.jpgs` можно сложить и картинки, и видео: перетащите их в
открытый архив, выберите «В один архив…» при шифровании или «Объединить файлы в один архив…» в меню.
К любой картинке или видео можно написать **заметку** (клавиша **N**): она хранится в самом файле
в зашифрованном виде и показывается поверх изображения. Обычные `.jpgs` без видео и заметок
по-прежнему открываются старыми версиями программы.

**Сжатие и конвертация (FFmpeg).** Правый клик → «Сжать / конвертировать…»: для видео — формат
(MP4 H.264/H.265, WebM VP9/AV1, MKV, GIF), качество, разрешение, кадры в секунду, звук, обрезка;
для картинок — JPEG/PNG/WebP, качество, размер. Расшифрованные данные при этом на диск не пишутся.

**Видео (`.vids`)** — любые форматы (mp4, mkv, webm, mov…) и анимированные GIF (анимация
сохраняется, GIF крутится по кругу), аппаратное декодирование, звук,
мгновенная перемотка по зашифрованному файлу. Панель управления, скорость, повтор,
сохранение кадра.

**Правый клик** — меню для изображения, архива и видео:

![Контекстное меню](docs/context-menu.jpg)

**Интеграция с системой:**
- миниатюры `.jpgs` / `.vids` в Dolphin, Nautilus, Nemo, Thunar;
- пункты «Открыть в JPGS», «Расшифровать сюда», «Зашифровать» в контекстном меню Dolphin / Nautilus / Nemo;
- ассоциация файлов, значки, ярлык в меню приложений.

## Установка

Зависимости: `python`, `python-gobject`, `gtk4`, `libadwaita`; для видео — `mpv` (libmpv) и `python-av`.

**Arch Linux (пакетом):**
```sh
git clone https://github.com/DiabloZet/jpgs.git
cd jpgs
makepkg -si
jpgs set-key          # задать ключ (или программа спросит при первом запуске)
```

**Любой дистрибутив, только для себя (без root):**
```sh
./install.sh          # спросит ключ; удаление: ./uninstall.sh
```

| Дистрибутив | Пакеты |
|---|---|
| Arch / Manjaro / EndeavourOS | `python-gobject gtk4 libadwaita mpv python-av` |
| Debian 13+ / Ubuntu 24.04+ | `python3-gi gir1.2-gtk-4.0 gir1.2-adw-1 libmpv2 python3-av` |
| Fedora 40+ | `python3-gobject gtk4 libadwaita mpv-libs python3-av` |

Нужны GTK ≥ 4.10 и libadwaita ≥ 1.5 (названия пакетов в других дистрибутивах могут немного отличаться).

## Ключи шифрования

Встроенного ключа нет. Ключ задаёт каждый пользователь:
- при установке (`install.sh` спросит),
- командой `jpgs set-key` (`--generate` — создать случайный),
- или в окне программы: при первом запуске либо *Меню → Ключи шифрования…*

![Ключ](docs/key-setup.png)

Вы вводите фразу — программа выводит из неё полноценный 256-битный ключ через **scrypt**
(N=2¹⁷, r=8: около 0,3–1 с и 128 МиБ памяти на каждую попытку — перебор на видеокартах
дорожает в сотни раз). Слишком короткие и простые фразы для новых ключей не принимаются
(не меньше 10 символов; лучше 4–5 случайных слов или «Сгенерировать»). Соль фиксированная,
поэтому одно и то же слово на другом компьютере даёт тот же ключ: файлы откроются, даже если
не переносить `keystore.json`.

**Несколько ключей — все сразу.** В окне *Меню → Ключи шифрования…* (или командой `jpgs keys`)
можно держать несколько именованных ключей. Файлы открываются **любым** из них: программа сама
подбирает нужный ключ к каждому файлу (по сигнатуре или проверке индекса — это быстро).
Активный ключ (✓) используется только для новых файлов. Ключи хранятся в
`~/.config/jpgs/keystore.json` (права `600`); слово можно задать и переменной окружения `JPGS_WORD`.

**Файлы из прежних версий (до 2.4).** Раньше слово использовалось как ключ напрямую, поэтому
старые файлы открываются «ключом старого формата». Существующий ключ переносится в хранилище
автоматически и продолжает работать. Чтобы перейти на стойкий ключ, не меняя слово:

1. *Ключи шифрования…* → кнопка со щитом у старого ключа (создаст ключ scrypt из того же слова;
   у ключей PBKDF2 из версии 2.4 программа попросит ввести слово);
2. согласиться перешифровать файлы открытой папки — или позже через «Сменить ключ у всех файлов
   папки…».

Одной командой то же самое:

```sh
jpgs keys list                                        # узнать id старого ключа
jpgs keys upgrade <id> --rekey *.jpgs *.vids --activate
```

Перешифровка идёт поблочно, на диск ничего не расшифровывается. Чтобы просто открыть старые файлы
(например, на другом компьютере), добавьте ключ с нужным типом: «Ключ из старых версий»
(`jpgs keys add --legacy`) или «Ключ из JPGS 2.4» (`--pbkdf2`); переменная `JPGS_KEY` тоже означает
старый формат.

**Смена ключа у файлов.** Уже зашифрованный файл можно перешифровать другим ключом, не
расшифровывая его на диск: «Сменить ключ файла…» в контекстном меню, «Сменить ключ у всех файлов
папки…» в меню, или `jpgs keys rekey ФАЙЛЫ --to <id>` в командной строке.

**Пароль на программу (необязательно).** Если задать пароль (*Ключи шифрования… → Пароль* или
`jpgs keys passwd`), список ключей на диске хранится зашифрованным (scrypt со случайной солью +
AES-256-CBC + HMAC), а сам пароль не записывается — хранится только проверка. При запуске программа
спросит пароль; после неверного ввода пауза растёт (1, 2, 4… до 30 с). В скриптах пароль можно
передать переменной `JPGS_PASSWORD`. Пароль необязателен: без него всё работает как раньше.

**Не спрашивать пароль каждый раз.** *Ключи шифрования… → Помнить пароль*: 5 минут … сутки.
После ввода пароля в `$XDG_RUNTIME_DIR` (каталог в памяти, только для вашего пользователя, очищается
при выходе из системы) кладутся ключи, выведенные из пароля, — не сам пароль — со сроком годности.
До его истечения программа (и миниатюры в файловом менеджере) открываются без вопроса.
**Ctrl+L** / «Заблокировать сейчас» / `jpgs lock` — забыть немедленно.

Отпечаток ключа (`jpgs key`) помогает сверить, что на двух компьютерах ключ одинаковый.

> ⚠ Без ключа (и без пароля, если он задан) файлы не открыть — сохраните их в менеджере паролей.
> Файлы, зашифрованные одним ключом, другим не открываются. Если забыть пароль, ключи не восстановить.

## Командная строка

```sh
jpgs файл.jpgs                  # открыть окно
jpgs encrypt a.jpg b.png clip.mp4 [-o папка] [--remove]
jpgs decrypt x.jpgs clip.vids [-o папка]
jpgs info *.jpgs *.vids
jpgs pack архив.jpgs a.jpg clip.mp4 b.jpgs [--remove]   # картинки и видео в один архив
jpgs note файл.jpgs [N] ["текст"]               # показать / задать заметку к записи N
jpgs lock                                       # забыть запомненный пароль
jpgs encryptor | merge | decoder | recovery   # пакетные команды для текущей папки
jpgs set-key [--generate | --stdin]  ·  jpgs key
jpgs keys list | add [--legacy | --pbkdf2] | remove <id> | use <id> | rename <id> ИМЯ | passwd [--remove]
jpgs keys upgrade <id> [--rekey ФАЙЛЫ] [--activate]   # усилить ключ (→ scrypt)
jpgs keys rekey ФАЙЛЫ --to <id>               # перешифровать файлы другим ключом
```

## Безопасность — честно

- **Перебор пароля.** Чтобы проверить догадку, злоумышленнику с вашим файлом нужно вывести ключ
  из фразы. Для ключей scrypt (по умолчанию с 2.5) это ~128 МиБ памяти и доли секунды на
  попытку — порядка тысячи попыток в секунду даже на мощной видеокарте. Случайная фраза из
  10+ символов или 4–5 слов при такой цене не подбирается. Короткие и простые фразы для новых
  ключей программа не принимает. Ключи PBKDF2 (2.4, ~в 30 раз дешевле для атакующего) и особенно
  «старого формата» (проверка — один блок AES) подбираются заметно быстрее: их стоит усилить.
- **Фиксированная соль** — сознательный размен ради того, чтобы одна фраза работала на любом
  компьютере. Это позволяет заранее посчитать таблицу для словаря частых паролей, но при цене
  scrypt такая таблица дорога и бесполезна против случайной фразы.
- **Шифрование файлов**: AES-256-ECB с PKCS#7 — как в исходной Java-версии, ради совместимости
  и случайного доступа к любому месту видео. Содержимое скрыто, но ECB не прячет повторяющиеся
  16-байтные блоки и не защищает данные от подмены. Индекс архивов v2 (список записей и
  заметки) шифруется AES-256-CBC и проверяется HMAC-SHA256 на отдельных подключах — его подмена
  обнаруживается. Для защиты от целенаправленной атаки используйте ещё и шифрование диска (LUKS).
- **Хранилище ключей** (`keystore.json`) без пароля лежит открытым — оно защищено только правами
  `600`. Само ключевое слово туда не пишется (только готовые байты ключа), но байты и есть ключ:
  кто прочитал хранилище — тот откроет всё. Закрывает хранилище только пароль на программу
  (scrypt со случайной солью → AES-256-CBC + HMAC-SHA256).
- **«Помнить пароль»**: пока срок не истёк, кто может читать файлы вашего пользователя в этом
  сеансе, может открыть хранилище. Не включайте на общем компьютере.
- **«Удалить оригиналы»** после шифрования удаляет файл, только если зашифрованная копия
  расшифровывается в точности в него, и удаляет безвозвратно, а не в корзину. На SSD и
  журналируемых ФС остатки данных могут сохраняться на диске — для гарантии нужен LUKS.
- **Миниатюры** в файловом менеджере хранятся **нешифрованными** в `~/.cache/thumbnails`.
  Если это нежелательно — отключите предпросмотр `.jpgs`/`.vids` и очистите кэш.
- «Сохранить копию», «Расшифровать» и «Копировать изображение» создают незашифрованные данные — только
  по вашей команде. Конвертация через FFmpeg расшифровывает только в память.

## Решение проблем

- **Видео: чёрный экран** — *Меню → Упрощённый вывод видео*, перезапустить программу.
- **Нет миниатюр видео** — установите `python-av`, затем `rm -rf ~/.cache/thumbnails/fail`.
- **KDE: нет пунктов меню / миниатюр** — `kbuildsycoca6 --noincremental`,
  `systemctl --user restart plasma-plasmashell`; в настройках предпросмотра Dolphin поднимите лимит размера файла.
- Отладка видео: `JPGS_MPV_LOG=/tmp/mpv.log jpgs файл.vids`.

## Разработка

```sh
python3 -m unittest discover -s tests -v
./bin/jpgs файл.jpgs    # запуск из исходников
```

| Модуль | Что делает |
|---|---|
| `jpgs/crypto.py` | AES (python-cryptography или OpenSSL через ctypes), хранение ключа |
| `jpgs/keystore.py` | несколько ключей, необязательный пароль (scrypt + AES-CBC + HMAC), запоминание |
| `jpgs/keys_ui.py` | окно управления ключами, запрос пароля, выбор ключа для перешифровки |
| `jpgs/container.py` | чтение `.jpgs`/`.vids` по блокам, поиск JPEG внутри, архивы v2 (видео, заметки), потоковое шифрование |
| `jpgs/transcode.py` | сжатие/конвертация через FFmpeg без расшифровки на диск |
| `jpgs/imaging.py` | декодирование JPEG под размер экрана |
| `jpgs/video.py` | libmpv через ctypes (поток из памяти, OpenGL-рендер), кадры через PyAV |
| `jpgs/viewer.py`, `video_ui.py` | интерфейс |
| `jpgs/cli.py` | командная строка и миниатюры для файловых менеджеров |
